# ADR-001: Serverless Edge Stack, Relational D1 Persistence, and Zero-Runtime-Dependency Architecture

Status: accepted
Date: 2026-11-12

## Context
Campus recruiters evaluating 500-800 engineering applications per open requisition need a deterministic operational knockout gate (`F-01`) and real-time candidate search/filter workspace (`F-03`) that persists evaluation records across recruiter workstations and cleared browser caches (`PROJECT.md`, `USERS.md`). Earlier prototyping confirmed that browser-only `localStorage` fails cross-device persistence, while heavy commercial ATS platforms or LLM-scored resume filters introduce recurring licensing costs, vendor lock-in, non-deterministic verdicts, and student PII exposure risks. Operating on a strict `$0/mo` student budget, our architecture must maximize stability, pricing predictability, institutional data privacy, and exit portability.

## The Gate
**Build** the core application in-house using vanilla web standards (`index.html`, `styles.css`, `app.js`), a stateless Cloudflare Worker edge API (`worker/src/index.js`), and Cloudflare D1 SQLite storage (`worker/schema.sql`), while **Delegation** is restricted strictly to initial static HTML/CSS layout scaffolding via Bolt.new (with zero ongoing runtime dependency) and **Buy** is rejected due to cost and lock-in.

Using our project weights (**Stability: 25, Pricing predictability: 30, Institutional fit: 25, Exit cost: 20**):
- **Build (Vanilla Web + Cloudflare Worker + D1) — Weighted Score: 92.75/100 (Chosen):** Zero runtime npm dependencies, hard `$0/mo` free tier (100,000 requests/day, 500 MB D1 storage), complete control over deterministic knockout rules (`F-01a`), and sub-4-hour portability via standard ANSI SQLite dumps and Web Fetch handlers.
- **Buy (Hosted BaaS — Firebase Firestore / Supabase) — Weighted Score: 69.00/100 (Rejected):** Proprietary client SDKs increase bundle weight and switching costs, while free-tier inactivity pauses and bandwidth step-ups threaten zero-budget predictability.
- **Delegate (Full-Stack AI-Hosted Builder) — Weighted Score: 60.00/100 (Rejected):** Black-box server hosting obscures trust boundaries for candidate qualification records and prevents local deterministic regression testing via `node --test`.

## Options considered
| Option | For | Against |
|---|---|---|
| **Build: Vanilla Web + Cloudflare Worker + D1** | Hard `$0/mo` free tier; zero runtime npm dependencies; 100% deterministic JavaScript knockout evaluation; parameterized `.bind()` SQLite storage; portable `.sql` dump exit in ~2–3 hours. | Requires manual handling of network drops and non-2xx HTTP responses in `app.js`, manual D1 schema migrations, and local `wrangler` dev tooling setup. |
| **Buy: Hosted BaaS (Firebase / Supabase)** | Built-in auth and real-time query SDKs out of the box; fast initial CRUD setup without writing raw SQL. | Proprietary SDK lock-in (~8+ hours to swap); rapid pricing jumps (`$25+/mo`) beyond small limits; third-party telemetry coupling on student records. |
| **Delegate: Full-Stack AI-Hosted PaaS** | Fastest initial visual deployment with zero manual infrastructure setup. | Opaque generated backend runtime; high platform lock-in (~12+ hours to exit); unvetted data routing violates career center privacy boundaries. |
| **Runtime LLM Resume Scoring (External API)** | Can parse unstructured prose resumes without rigid formatting rules. | Violates deterministic reproducibility (`F-01a`); incurs per-token API costs; creates student PII leakage risk across external AI endpoints. |

## Decision
Chose **Build**:
1. **Frontend (`index.html`, `styles.css`, `app.js`):** Semantic HTML5, design-token CSS (`context/DESIGN.md`), and vanilla ES modules using safe DOM APIs (`textContent`, `replaceChildren()`) with zero external CDN scripts.
2. **Edge API (`worker/src/index.js`):** A stateless Cloudflare Worker exposing `GET /entries` and `POST /entries` with explicit CORS origin validation and deterministic server-side input validation.
3. **Database (`worker/schema.sql` on Cloudflare D1):** Serverless SQLite storage (`mgt3745-entries`) accessed strictly via prepared statements with `.bind(...)`, keeping `wrangler` (`^4`) isolated to `devDependencies`.
4. **Trust Boundaries:** Candidate qualification payloads cross `Browser -> Worker -> D1` over HTTPS; no candidate PII or runtime API keys ever cross to external generative AI endpoints.

## Consequences
### Positive
- Ships **zero** third-party runtime npm dependencies to production, eliminating transitive runtime supply-chain risk.
- Evaluated candidate records persist across devices and cleared browser caches while remaining exportable as standard SQLite `.sql` files.

### What Gets Harder
- **Explicit Network Error Handling:** Every read/write crosses the network; `app.js` must catch offline drops and HTTP `400`/`500` errors and display them via `textContent` without throwing console errors.
- **Manual Schema & Origin Maintenance:** D1 schema migrations (`worker/schema.sql`) and allowed CORS origins in `worker/src/index.js` must be updated manually when deployment URLs change.
- **Dev-Tooling Footprint:** While production ships zero packages, `wrangler` (`^4`) pulls in a large local dependency tree (`workerd`, `miniflare`, `esbuild`, `sharp`) inside `node_modules` during local development.

### Reversal Trigger
Revisit and amend this ADR if:
1. Daily Worker volume exceeds **80,000 requests/day** (80% of Cloudflare's 100k free-tier cap) or D1 storage exceeds **400 MB**.
2. Institutional requirements expand to require multi-tenant university SSO login or real-time WebSocket push updates across concurrent recruiter workstations.
3. Cloudflare alters free-tier pricing or D1 availability terms.
